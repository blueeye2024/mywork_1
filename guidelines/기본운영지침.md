# 기본 운영 지침 (Operations Manual)

이 문서는 **[Cheongan]** 프로젝트의 일상적인 운영, 배포, 모니터링 방법을 정의합니다.

## 1. 자동 배포 (Authorization Deployment)

코드를 수정한 후 서버에 반영하려면 다음 단계를 수행합니다.

1. 로컬에서 코드 개발 및 테스트
2. Git Commit & Push
3. **운영 서버** 접속 (`ssh -p 1975 blue@114.108.180.228`)
4. 배포 스크립트 실행:
   ```bash
   ./deploy.sh
   ```
   > **Note**: 이 스크립트는 `Git Pull`, `Version Up`, `Build`, `Health Check`, `Logging`을 모두 자동으로 수행합니다.

## 2. 로그 및 모니터링

서버 상태를 확인하려면 다음 도구(스크립트)를 사용하십시오.

| 명령어 | 기능 | 설명 |
|---|---|---|
| `./logs.sh` | **실시간 로그 보기** | 백엔드/프론트엔드 로그를 실시간으로 출력합니다. (종료: Ctrl+C) |
| `./status.sh` | **리소스 사용량** | CPU, 메모리 점유율을 확인합니다. |
| `docker ps` | **프로세스 확인** | 현재 실행 중인 컨테이너 목록을 봅니다. |

## 3. 긴급 복구 (Rollback & Fix)

배포 후 심각한 오류가 발생했을 경우:

1. **로그 확인**: `./logs.sh`로 에러 원인 파악.
2. **이전 버전 롤백**: (현재는 Git Revert 후 재배포 권장)
   ```bash
   git reset --hard HEAD^
   ./deploy.sh
   ```
3. **컨테이너 전체 재시작**:
   ```bash
   docker-compose down
   ./deploy.sh
   ```

## 4. 데이터베이스 백업 및 관리

- **DB 정보**: MariaDB (112.175.54.59)
- 이 프로젝트는 외부 DB를 사용하므로, 컨테이너 내부에는 영구 데이터가 저장되지 않습니다. DB 백업은 별도 DB 서버 정책을 따릅니다.
